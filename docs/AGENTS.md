# 文档维护

修改文档前阅读根 `AGENTS.md` 和[文档规范](standards/12_documentation.md)。按根指令报告编码视角，并说明本次文档目的及适用路径。

## 目录与导航

顶栏使用：首页、教程、项目规范、参考、需求文档、AI 协作。

- `index.md`、`home/`：项目介绍、分布式单体、项目结构、身份、权限、认证和 IoT 概念。
- `tutorials/`：完成具体任务的操作方法，共 16 篇。内容按任务顺序组织，章节形式由操作本身决定。
- `standards/`：工程原则、结构、分层、命名、Java、持久化、数据库、前端、注释日志、构建、插件、测试、评审、文档，共 14 篇。
- `reference/`：Java API 入口、HTTP 通用契约、Sca4d Server HTTP API 和运行配置。
- `requirements/`：业务需求与实现设计。
- `ai-collaboration/`：任务准备、方案确认、修改和验收方法。

长期页面必须进入 VitePress 侧边栏。增加页面前先检查已有页面能否容纳该任务；新增顶层模块或改变目录分类需取得任务发起人确认。禁止创建占位页。

## 内容要求

Sca4d-J 的架构称为「分布式单体」：业务体系保持完整，单实例与集群使用同一套业务实现和数据约束。模块描述代码归属及功能选择，不用「模块化单体」替代项目定位。具体设施的集群限制要按当前实现写清楚。

Redis 和 RabbitMQ 是固定基础设施。认证方法和存储后端按已实现扩展点说明。Vben 是默认管理端示例，布局、表格、表单等通用用法链接官方文档。

采用 `tech-doc-style-chinese` 的事实保真和中文技术写作规则，项目约定与任务发起人的明确要求优先。直接说明对象、用途、条件、操作和结果。删除常识解释、虚构对比、刻意口语和文档调整历史。不能为了缩短文章删除仍有效的条件、例外、失败结果、示例或验收要求。

教程核对当前源码、配置和测试。设计目标与实现的差距在交接中报告，不将尚未实现的接口写成可以直接运行的教程。Java API 的签名、参数、返回值和异常来自源码 Javadoc。

## 链接与验证

Java API 使用 `/javadoc/<Gradle 项目路径>/<包路径>/<类型>.html`；包使用 `package-summary.html`，项目使用 `index.html`。页面合并时同步修改链接和锚点，链接文字应准确说明目标内容。

`public/javadoc/` 保存纳入版本管理的 Java API 生成结果。修改公开类型、签名或文档注释后，运行根任务 `collectJavadoc` 更新并随源码提交；只修改源码，不手工编辑生成的 HTML。目录由 Sync 任务完整同步，已删除类型的旧页面也会移除。

每次修改完整重读页面、检查 diff 并运行 `git diff --check`。导航和内部链接变化运行文档构建；包含 Java API 的交付按[文档构建规范](standards/09_build.md)生成完整站点。VitePress 不检查 Javadoc 链接，需要对照生成文件验证。限制构建资源，不运行与文档变化无关的产品测试或浏览器验收。
