# AI 执行规则

## 适用范围

本规则适用于使用 AI Agent 规划、实现、检查、记录和提交 Sca4d-J 项目修改的任务。

## 人与 Agent 的职责

- 人确定最终目标、范围、业务取舍和验收条件。
- Agent 读取项目、提出实现计划、执行修改并提供验证结果。
- 需求存在多个有效解释时，Agent 必须请求确认。
- Agent 不得自行增加业务要求、放宽项目规则或扩大提交范围。

## 计划确认

修改文件前必须完成计划。计划至少包含：

- 当前代码和运行方式；
- 最终需要交付的用户结果；
- 明确不修改的内容；
- 数据、接口、页面和外部服务的处理方式；
- 失败结果与兼容要求；
- 测试和验收方法。

用户未确认最终结果或关键取舍时，Agent 继续调查或提问，不进入实现。

## 读取要求

Agent 必须读取：

1. 任务涉及的完整源码、配置、迁移、测试和文档；
2. `docs/standards/` 下每一篇项目规范；
3. 与任务相关的系统设计、开发指南、内置功能、运维和参考页面；
4. 当前工作树中的未提交修改。

目录索引、搜索摘要和 Git diff 只能用于定位文件，不能代替完整文件内容。

## 修改要求

- 按确认后的计划修改，不把实现过程中的临时想法写入公共 API 或数据库。
- 使用项目已有的业务名称、目录、接口和错误处理方式。
- 保留用户已有且与任务无关的修改。
- 发现计划与当前代码冲突时停止相关修改，说明冲突位置和可选结果。
- 不通过增加兼容分支、中间类型或旁路实现掩盖没有确认的决定。

## 执行循环

每次循环选择一个可以验证的结果，例如一个数据库修改、一个后端接口、一个管理端操作或一组文档更新。完成后立即运行对应检查，并记录结果。

检查失败时先判断原因：实现错误、环境缺失、外部服务不可用或测试覆盖不足。不得忽略失败命令，也不得在没有证据时标记完成。

## 人工接管记录

每个工作批次结束时报告：

- 当前 Goal；
- 已确认的决定；
- 已完成内容；
- 剩余内容；
- 修改文件；
- 已运行命令和结果；
- 当前错误或阻塞条件；
- 下一项可以直接执行的工作。

报告必须与当前工作树一致，不把已经完成或已经删除的工作继续列为待办。

## 人类文档

代码、配置、接口、数据库或运行方式发生变化时，Agent 必须更新对应的人类文档。非 AI 章节只面向项目用户和维护者，不包含 Agent 的思考过程、任务对话、执行记录、临时提示词或回复格式。

修改既有页面前，Agent 必须建立原文到新位置的内容清单。规则、条件、例外、失败结果、示例和验收要求缺少任何一项时，文档修改未完成。

完整要求见[使用 AI 交付可维护代码](./tutorial#维护人类文档)和[文档审查与完成标准](/documentation/review)。

## 全文件审查

实现完成后，Agent 必须：

1. 列出全部新增、修改、重命名和删除文件；
2. 读取每个文件的完整内容；
3. 按 34 篇项目规范逐条检查；
4. 运行受影响模块的测试、格式化、构建和文档检查；
5. 修复全部问题后重新执行检查。

任意一条项目规范不符合时，整个任务不得通过。测试成功、修改规模较小、Token 消耗较高或任务已经持续较长时间都不能降低检查要求。

## 提交条件

只有同时满足以下条件时才允许创建提交：

- 最终目标和验收条件全部完成；
- 计划中的旧路径和临时代码已经删除；
- 每个修改文件已经完成全文件审查；
- 项目规范检查没有遗留问题；
- 相关测试、格式化、构建和文档检查通过；
- 工作树中没有混入与 Goal 无关的修改；
- 提交内容可以由另一位维护者继续修改。

一次 Goal 通过检查后创建一次提交。检查未通过时继续修复，不创建用于绕过门禁的临时提交。

## 规则修改

Agent 修改项目规范或 AI 执行规则时，修改前的规则继续约束本次任务。只有人确认新规则后，后续任务才采用新内容。

发现两篇规则冲突时，Agent 记录文件、具体条款和两种实现结果，并请求人确定唯一要求。不得选择要求更低的一项继续实现。
