# 记录新的内置功能

## 目标

为多个业务模块共用的接口和实现补充使用步骤、强制规则、运行要求和查询信息。

## 前置条件

- 至少两个已实现的业务场景需要使用该功能，或者该功能作为独立服务运行。
- 公共接口、默认实现、配置项和失败结果已经确定。

## 操作步骤

### 1. 说明负责的对象和操作

在系统设计中写明该功能读取和修改的数据、调用的外部服务、与相邻模块的分工，以及多个应用实例同时运行时的处理方式。不要用实现类名或中间件名称代替这些说明。

### 2. 写入项目规则

在 `standards/facilities/` 记录必须使用的入口、禁止的旁路、集群限制、失败处理和使用条件。每条规则提供可以检查的正确示例、错误示例或验收方法。

### 3. 编写内置功能页面

页面依次说明：

1. 处理的对象和操作；
2. 公共接口和默认实现；
3. 接入步骤；
4. 配置项和外部服务；
5. 失败结果和恢复方法；
6. 可以运行的示例。

业务模块组合这些接口的完整步骤写入 `development/`，不在两个位置复制同一教程。

### 4. 补充运维和参考手册

新增外部服务、配置、任务、健康检查、日志、指标或故障处理时更新 `operations/`。配置键、接口、注解、枚举、事件和模块位置写入 `reference/`，并从当前源码核对名称和默认值。

### 5. 验证实际使用

至少验证一个业务调用、多个实例同时运行的结果和一个失败场景。只有多个接口必须按固定顺序组合时，才增加完整开发教程。

## 运行结果

开发者可以完成接入，运维人员可以配置和排查，参考手册可以查询准确参数，项目规范可以直接用于代码审查。
