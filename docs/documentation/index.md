# 维护项目文档

项目文档按读者要解决的问题分类。代码、配置或运行方式发生变化时，修改负责说明该内容的页面，并检查引用该页面的其他位置。

## 文档分类

| 分类 | 内容 |
| --- | --- |
| 作者的话 | 项目起源，以及脚手架采用当前工程结构的设计思想 |
| 项目手册 | 项目定位、首次运行、日常开发、构建和项目采用步骤 |
| 系统设计 | 应用组成、请求处理、身份、权限、数据和多实例运行方式 |
| 开发指南 | 完成 Web API、数据访问、权限、消息、文件和管理端功能的步骤 |
| 项目规范 | 后端、网关、管理端、数据库、测试和文档必须遵守的规则 |
| 内置功能 | 缓存、消息、文件、调度、通知等现有功能的使用方式 |
| 运维 | 环境配置、构建产物、部署、日志、健康检查和故障处理 |
| 参考手册 | 配置键、HTTP 接口、Java 类型、枚举、错误码和模块位置 |
| AI 协作 | 使用 Agent 计划、实现、检查和交接任务的方法 |

## 内容归属

一个名称、参数或规则只在一个页面完整说明。其他页面只保留当前任务需要的内容，并链接到完整说明。

例如，`Subject` 和 `Account` 的定义位于系统设计；登录接口位于参考手册；接入登录的操作步骤位于开发指南；认证代码必须遵守的规则位于项目规范。
