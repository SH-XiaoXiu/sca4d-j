# 记录新的业务功能

## 目标

在交付业务功能时，更新所有受影响的说明、规则和参考页面。

## 前置条件

- 已确认业务对象、状态变化、公开接口、数据变化和验收条件。
- 已列出新增、修改、重命名和删除的代码文件。

## 操作步骤

### 1. 列出对外变化

记录新增或修改的业务对象、状态、权限、数据访问条件、HTTP 接口、配置和外部事件。私有方法、局部实现步骤和单个页面内部状态不需要进入系统设计。

### 2. 选择文档位置

| 内容 | 更新位置 |
| --- | --- |
| 项目定位、顶层模块、启动方式 | 项目手册 |
| 应用组成、请求处理、身份、权限、事务或多实例行为 | 系统设计 |
| 可以重复使用的开发步骤或完整示例 | 开发指南 |
| 后续实现都必须遵守的规则 | 项目规范 |
| 多个业务模块使用的公共接口和实现 | 内置功能 |
| 配置、外部服务、任务、部署、指标或故障处理 | 运维 |
| 路由、配置键、枚举、注解、接口、错误码或模块位置 | 参考手册 |

只影响当前业务的决定保留在对应业务教程中，不写成整个项目都要遵守的规则。

### 3. 核对代码和生成内容

- 从 Controller 和当前运行应用的 OpenAPI 核对路由、请求和响应。
- 从 Flyway 迁移、Entity、Mapper 和 SQL 核对数据库变化。
- 从 Properties、YAML、`.env.example` 和 Compose 核对配置。
- 重新生成管理端 OpenAPI 类型，并检查实际调用。

### 4. 构建并检查文档

```bash
cd docs
pnpm docs:build
```

检查新增页面的侧边栏入口、站内搜索、内部链接、桌面和窄屏布局。没有修改的文档分类记录为“不适用”，并写明原因。

## 运行结果

代码、测试、接口、数据库、配置和文档描述同一个版本的行为。
