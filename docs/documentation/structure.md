# 文档结构

## 是什么

文档站包含作者的话、项目手册、系统设计、开发指南、项目规范、内置功能、运维、参考手册、AI 协作和文档维护。每个分类对应一种固定的查询方式。

“作者的话”记录项目起源和设计思想，属于 Concept，不定义强制工程规则。实现要求以项目规范为准。

## 为什么按问题分类

读者通常从任务出发查找内容：第一次运行项目、增加接口、查询配置键、部署应用或处理故障。按问题分类后，读者不需要知道某个功能由哪个提交、哪个类或哪位维护者完成。

分类也限制页面内容。操作步骤进入教程，系统组成进入概念说明，强制规则进入 Specification，准确参数进入 Reference。一个页面不同时承担多种写作任务。

## 工作方式

每项内容选择一个主要页面：

- 系统对象及其关系在系统设计中说明。
- 完成开发任务的步骤在开发指南中说明。
- 所有实现都要遵守的规则在项目规范中说明。
- 配置键、路由、类型和枚举在参考手册中列出。
- 部署、观测和故障处理在运维中说明。

其他页面引用主要页面，不复制整套参数或规则。文件可以为改善阅读顺序而拆分，但同一内容不能形成多个互相冲突的版本。

## 示例

新增租户订单查询接口时：

- 开发指南说明 Request、Repository、Service 和 Controller 的实现步骤。
- 参考手册记录 HTTP 路由、请求参数、响应和错误码。
- 权限页面记录新增权限及其使用位置。
- 数据访问规则没有变化时，不修改系统设计和项目规范。

只有接口改变现有请求处理方式时才修改系统设计；只有它产生后续功能都必须遵守的新规则时才修改项目规范。
