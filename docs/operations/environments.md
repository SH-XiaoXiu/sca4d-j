# 环境划分

## 环境 Profile

应用必须且只能激活一个可识别环境：

| Profile | BootEnvironment | 用途 |
| --- | --- | --- |
| `local` | `LOCAL` | 开发者本机 |
| `dev` | `DEV` | 共享开发 |
| `test` | `TEST` | 自动化与测试环境 |
| `staging` | `STAGING` | 上线前生产等价环境 |
| `prod` | `PROD` | 生产环境 |

同时激活多个环境或没有可识别环境时启动失败。功能开关不应伪装成 Profile。

## 本地环境

可使用 Compose、回环地址和开发凭据，数据允许重建。即使本地也必须通过 Flyway 和真实认证链，不能靠静态假数据替代首次运行。

## 测试环境

配置固定、可复现，测试数据有明确初始化和清理。集成测试使用隔离 schema/实例，不能依赖开发者本机残留 Flyway 历史。

## staging 与生产

按生产安全标准处理：默认凭据和宽松 Origin 禁止，OpenAPI 按策略关闭，BootCheck REQUIRED 失败阻止接流量，可信代理正则收紧到实际网段。

## 环境差异

地址、凭据、容量、日志级别和可选能力由配置表达。业务源码、迁移历史和接口契约不得按环境分叉。环境特有操作应进入部署编排或受控脚本。
