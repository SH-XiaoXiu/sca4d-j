# 01 工程设计原则

长期维护中的代码应当可预测。熟悉一类功能的开发者，能够根据已有实现判断新代码的位置、名称、调用方式和失败结果。稳定的业务概念、连续可读的流程和一致的实现方式，比减少文件或追求设计模式更有价值。

## 稳定的操作与变化的场景

核心操作表达长期成立的业务含义。假设 `createOrder(...)` 表示创建订单，人工创建、批量创建和后台导入可以各自处理权限、输入与外部副作用，再共用确实相同的订单创建行为。仅因这些场景最终写入同一张表，就把差异塞进布尔参数和可空选项，会使 `createOrder(...)` 的含义随场景增加而改变。

共用行为取决于输入、规则、状态变化、失败结果和副作用是否相同。场景之间只有 SQL 相似时，可以保留各自的业务流程；数据写入方式仍可在持久化层复用。

## 抽象表达当前问题

抽象是围绕一个问题，选取对象或过程相关的特征、行为与关系，暂时舍弃无关细节，形成可用于设计和实现的模型。讨论订单能否提交时，订单状态、明细和提交规则与问题有关，页面排版和数据库列名没有参与这一判断。讨论页面展示时，关心的是用户需要看见的状态与金额；讨论持久化时，关心的是需要保存并保持一致的数据。这些问题分别决定模型保留什么，页面组件和表结构再负责具体实现。

类、接口、数据类型和函数都可能表达抽象。抽象是否成立取决于模型能否准确回答当前问题，并保留会改变结果的差异；是否公开、是否复用、是否已有多个实现都不是定义条件。`PermissionEvaluator` 可以表达权限判断这一操作，`Order` 也可以表达订单及其状态关系，两者不必具有相同的复用方式。

## 封装维护对象状态

封装把内部状态和影响状态的行为组织在一起，控制外部的访问方式，使对象能够维护自己的约束。例如，订单若规定只有待提交状态可以提交，外部代码就不能任意写入状态；提交操作负责检查条件并完成变化。

抽象决定当前问题需要表达哪些含义，封装决定外部怎样使用这些含义并改变内部状态。一个模型可以选择正确的概念却暴露了不该直接修改的字段，也可以严密限制字段访问却没有表达真实业务对象。

## 完整业务流程可以连续阅读

业务动作的校验、判断、写入和副作用共同决定结果。把流程拆成 `prepare`、`build`、`execute` 和 `after` 等私有步骤，可能让每个方法变短，却要求阅读者在多处重新拼接顺序。较长的方法只要始终处理同一个业务动作，且条件与结果清楚，就不因行数需要拆分。

私有方法可以表达有意义的操作，即使只有一个调用方。复杂算法、协议转换和不直观的判断适合单独命名；关键写入时机、事务范围和外部副作用仍应能从主流程看出。提取方法是代码组织手段，本身不证明产生了新抽象。

## 名称与输入说明真实行为

类型、方法、字段和路由共同构成团队描述业务的语言。`disableAccount`、`replacePermissions` 和 `claimForDispatch` 说明对象与动作；孤立的 `process`、`handle` 和 `execute` 通常要求阅读者进入实现才能确定含义。框架规定的回调名称属于框架的接口约定，按所在语境理解。

核心操作的必要输入和会影响结果的条件应当可见。一组数据已经形成独立概念时，可以包装为对象；仅为减少参数个数创建 `Context` 或 `Options`，容易把无关状态汇集到一个可变容器。权限、事务、锁和外部调用的执行位置也会影响调用者对结果的理解。

系统定义且取值有限的状态适合用类型约束。开放编码则需要说明来源、校验位置和未知值的结果；数据库或 HTTP 最终使用字符串，不要求内部也放弃类型信息。

## 长期数据与临时状态

数据库保存需要长期存在、需要并发保护或无法可靠重建的事实。页面临时选择和一次请求的中间结果通常不进入长期数据模型。派生结果需要持久化时，写入者、更新时间、失效与修复方式都成为模型的一部分。

一个事实可以在数据库、缓存和页面中出现，但需要明确哪个位置负责更新，以及其他表示怎样同步或失效。名称、字段和路由若同时保留两套相近含义，调用者就必须自行猜测哪一套是当前约定。

## 重复的代码结构与共用实现

经过验证的目录、API 和调用方式形成可预测的样板。重复的代码结构可以帮助开发者辨认职责；只有相同原因会共同变化的行为才值得提取为共用实现。已有框架和项目入口已经准确表达的行为，也不需要另一层同义包装。

例如，账号和角色的列表接口都按相同顺序完成范围限制、分页和响应转换，这种重复让新接口的位置与写法容易预测。两者的权限规则不同，不能仅因调用顺序相似就合并成接收通用 Map 的查询器。

## 旧入口退出后的代码

旧实现退出前，需要处理仍在使用它的消费者、数据迁移、发布与回滚。条件满足后，源码保留当前有效的名称和行为；历史由版本记录保存，过期的转发入口和兼容分支不再占用读者的判断成本。
