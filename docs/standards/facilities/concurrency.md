# 并发规则

## 乐观锁

可编辑主数据使用版本条件原子更新。禁止先查版本再无条件写；冲突统一抛并发异常、返回 409 和刷新反馈。

## 幂等

只对语义允许重放的入口使用 `@Idempotent`。key 与请求指纹共同校验；同 key 不同 body 必须冲突。幂等不能替代业务唯一约束。

## 分布式锁

锁 key 必须唯一对应竞争资源，取得锁后再次查询数据库中的当前值。禁止用全局大锁掩盖数据模型问题，禁止依赖 JVM `synchronized` 解决集群竞争。

## 限流

限流维度、容量、恢复速率和失败响应必须显式。多实例入口使用共享 Redis 实现；匿名与认证入口选择真实存在的 key 维度。

## 组合顺序

同时使用多种注解时，必须通过测试确认 AOP 执行顺序、事务开始和提交位置、锁释放时机、幂等结果写入和失败恢复。异常不得留下永久的处理中记录或错误的成功缓存。

## 选择原则

数据库约束保证数据有效；乐观锁处理更新冲突；幂等处理重放；分布式锁处理必须串行的副作用；限流处理频率。禁止互相替代。
