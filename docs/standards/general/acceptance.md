# 验收规则

本页定义日常变更的最低验收条件。完整质量要求见[工程验收原则](/standards/philosophy/acceptance-principles)，文件覆盖要求见[代码评审覆盖规范](./review-execution)。

## 单一语义

一个名称、类型、字段和 API 只能表达一个语义。同名多义或同义多名不符合验收条件，旧表达必须从当前实现中删除。

## 修改所有相关文件

修改功能时，检查源码、数据库迁移、配置、HTTP 接口、前端、测试、文档和旧实现。不能只修改其中一个调用路径，并保留另一个行为不同的旧路径。

## 证据优先

验收证据来自代码、SQL、请求响应、日志、页面、测试输出或构建产物。未覆盖目标行为的成功命令不能证明功能完成；未发现错误也不能证明行为正确。

## 只修改相关文件

变更只包含目标功能及其必要依赖，不包含旁支重构。目标范围内的旧实现和无效兼容必须完整删除。

## 读取相关代码

修改文件的验收范围包含完整职责、公共方法、调用位置和测试，不能缩小到 diff 片段。新代码与文件已有行为的冲突必须在同一变更中消除。

## 失败关闭

认证、权限、数据范围、签名、配置校验和关键依赖异常时必须安全失败。禁止因解析失败、空集合、未知枚举或服务异常自动放宽为全权限、全部范围或默认成功。
