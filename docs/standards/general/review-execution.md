# 代码评审覆盖规范

## 覆盖范围

一次完整代码评审包含以下内容，缺少任一项都视为覆盖不完整：

1. 最终需求、确认方案、仓库规范和相关专题文档；
2. 使用 `git status --short`、`git diff --name-status -M <base>` 和 `git ls-files --others --exclude-standard` 建立全部改动文件库存。
3. 确认 staged、unstaged、untracked、rename 和 deleted 文件均已进入库存。
4. 逐个打开每个新增、修改和重命名文件的完整内容，不只阅读 diff hunk；删除文件读取删除前完整内容并检查消费者清理。
5. 对 Java 文件执行分层依赖、公开 API、私有方法、框架使用、注释和测试审查。
6. 对 SQL、Mapper、Repository 和持久化 Service 完整执行[持久化分层完整规范](/standards/stack/persistence-boundary)。
7. 对列表、分页、循环和批处理量化数据库与外部调用次数，检查 N+1 和可批量化操作。
8. 对状态迁移、任务、消息、缓存、锁和外部副作用证明集群并发、重复执行与失败恢复成立。
9. 沿改动契约检查必要消费者、配置、迁移、测试和文档。
10. 前端变更逐页面执行[前端质量完整规范](/standards/stack/frontend-quality-review)，验证全部目标 viewport、交互状态和真实 API。
11. 覆盖数据、全部问题和验收结果。

每个改动 Java 文件必须具有以下审查记录：

```text

依赖方向：通过/不通过
公开 API：通过/不通过

文档注释：通过/不通过
逻辑注释：通过/不通过
框架使用：通过/不通过
N+1 与调用数量：通过/不通过
集群成立性：通过/不通过
测试契约：通过/不通过
日志阶段与级别：通过/不通过
日志来源与敏感数据：通过/不通过
包归属：通过/不通过

```

任一项为“否”或“不通过”时，该文件不符合验收条件。

## 强制扫描

Git 库存和静态搜索只用于发现候选和证明覆盖，不能代替源码审查。覆盖证据至少包括：

- 所有改动 Java 文件数量与实际状态一致；
- 所有 Service 文件均已检查是否直接依赖 Mapper；
- 所有 Controller 文件均已检查是否越过 Service；
- 所有 Repository 与 Mapper 方法均已建立对应关系；
- 所有私有方法均已分类；
- 所有接口和接口方法均已检查文档契约；
- 所有非平凡方法均已检查中文逻辑注释；
- 所有新增类型和公共实现入口均已搜索重复实现及旁路入口。
- 所有 Entity、领域模型、Request、Result、View、Mapper 查询结果和 Service 契约的有限状态/类型/模式/操作字段均已检查类型安全枚举；
- 所有改动前端文件和页面均已完整阅读并按前端质量规范审查；
- 桌面、紧凑桌面、平板和手机的业务能力、溢出、遮挡和交互反馈均有运行证据；
- 所有列表、分页、循环和批处理均已量化 SQL 与外部调用次数并检查 N+1；
- 所有状态迁移、任务、消息、缓存、锁和外部副作用均已检查集群竞争、幂等和失败恢复。
- 所有业务阶段和必要技术边界均已检查 INFO、DEBUG、WARN、ERROR 的选择与字段完整性；
- 所有应用日志均可由 `%source` 得到模块和实际类名，消息不包含秘密、完整 Payload 或重复异常；
- 所有新增、修改和移动类型均已检查领域根包、职责子包以及 Util/Helper 的真实职责。

## 不合规情况

出现以下任一情况时，代码评审覆盖不完整或变更不符合规范：

- 没有建立包含 tracked、untracked、rename 和 deleted 文件的完整库存；
- 存在未打开完整内容的改动文件；
- 只检查新增行，没有检查改动文件原有代码；
- 使用抽样代替逐文件审查；
- Service 直接依赖 Mapper；
- 存在用 String 表达系统定义有限状态、类型、模式或操作的字段，或开放字符串标识没有说明扩展来源；
- 存在可稳定批量化的 N+1 或逐行数据库操作；
- 逻辑依赖单实例、进程锁或单机调度才能成立；
- 私有方法尚未完成能力分类；
- 注释只检查数量，没有检查契约质量；
- 测试只验证内部实现，没有验证真实边界；
- 前端存在未审查页面、未验证 viewport 或违反前端质量规范的实现；
- 业务流程缺少阶段日志，或日志级别、字段、失败结果和敏感数据处理不合规；
- 改动类型位于不表达其职责的包，或 Util/Helper 实际承载业务流程；
- 差异规模超过当前评审能够完整覆盖的范围。

差异规模超过单次评审覆盖范围时，提交必须按可以完整审查的职责边界拆分，不能使用抽样结果代替完整覆盖。
