# 命名、类型与显式契约

## 命名

类、方法、字段和路由必须使用项目业务语言。动词说明动作，名词说明稳定对象；禁止 `process`、`handle`、`data`、`info` 等无法预测职责的泛化名称。

Request 只用于 HTTP 输入，View 只用于 HTTP 输出。一次操作返回值必须使用说明业务语义的类型名，不能以泛化 `result` 包收纳；Entity 映射数据库表并允许 Service 直接复用。Entity 不得直接进入 HTTP 响应或 View；不得为规避 Entity 名称复制字段完全相同的类型，也不得为同一对象同时维护 DTO、VO、BO 等重复类型。

`Util` 和 `Helper` 不是禁用后缀，但必须准确描述真实的无状态通用操作或有限技术协助。承载状态机、事务、持久化编排和副作用顺序的类型必须使用业务能力名称。完整判断见[代码结构与分包](./code-structure)。

## 类型

有限状态必须使用枚举或封闭类型，不使用魔法字符串和整数。ID、时间、金额、权限动作和访问范围使用稳定类型；不同领域 ID 不得因底层都是 `Long` 就随意互换。

生产代码和测试代码均禁止声明 `record`。需要不可变值对象时使用语义明确的普通类，并显式声明构造器、字段访问和约束。

## 显式契约

公共和核心方法的必要输入必须出现在签名。不得从全局可变状态、ThreadLocal 或通用 Context 偷取本应由调用者明确提供的业务参数。请求级认证事实只能从统一 CurrentRequest 获取。

## 空值

空值必须有明确业务含义，并通过 JetBrains nullability、Optional 或结果类型表达。禁止用 `null` 同时表示不存在、无权限、全部范围和系统错误。

## 有限状态

枚举反序列化拒绝未知值；开放字符串只用于真正开放的外部编码。状态转换由业务流程控制，不允许 Controller 或 Mapper 随意写入任意状态。
