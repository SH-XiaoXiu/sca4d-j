# Sca4d-J 工程规范

工程规范用于决定代码放在哪里、接口怎样表达、数据由谁维护，以及修改后怎样验证。新增功能先读工程原则和对应技术规范，交付前读测试与评审要求；不需要为一次局部修改运行全部检查。

## 阅读顺序

新增功能先阅读[工程原则](./01_principles)，再根据修改位置阅读[架构与边界](./02_architecture)、[代码结构](./03_code-structure)或对应的技术规范。完成实现后，按照[测试与验证](./11_testing)和[代码评审](./12_review)检查结果；修改文档时阅读[文档规范](./13_documentation)。

## 工程原则

- [01 工程原则](./01_principles)：说明稳定核心、抽象、显式契约、连续阅读、证据和范围判断。
- [02 架构与边界](./02_architecture)：说明分布式单体、目录职责、模块依赖、公开接口和分层。
- [03 代码结构](./03_code-structure)：说明命名、类型、包结构、私有方法、`Util` 和 `Helper`。
- [04 Java 与 Spring](./04_java-and-spring)：说明 Java 类型、Spring 装配、事务和失败处理。

## 技术实现

- [05 SQL 与持久化](./05_persistence)：说明 Service、Repository、Mapper、查询、写入、并发、缓存和批处理。
- [06 数据库](./06_database)：说明 PostgreSQL 表结构、约束、索引和 Flyway。
- [07 Vue、TypeScript 与交互](./07_frontend)：说明管理端契约、状态、权限、布局和交互。
- [08 注释、文档注释与日志](./08_comments-and-logging)：说明源码注释、TSDoc 和运行日志。

## 构建与验收

- [09 格式化与构建](./09_build)：说明局部检查、文档站和生成物构建。
- [10 Sca4d-J 构建 Gradle 插件](./10_gradle-plugins)：说明统一构建阶段、质量报告和 App 迁移生成。
- [11 测试与验证](./11_testing)：说明怎样选择能够发现问题的检查。
- [12 代码评审](./12_review)：说明文件覆盖、分层审查和验收证据。

## 文档

- [13 文档规范](./13_documentation)：说明页面职责、事实核对、正文表达、链接和文档构建。

规范之间可以互相引用，但一项规则只在一个页面完整说明。页面标题和链接名称使用开发者查找对象时会使用的名称，不为形式完整增加重复页面。
