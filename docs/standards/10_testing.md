# 10 测试与验证

验证的对象是代码可能改变的行为。编译、单元测试、集成测试、构建和实际页面检查回答不同的问题；某项检查通过，只能说明它覆盖到的条件成立。

## 不同检查回答什么问题

| 检查 | 能证明的内容 | 不能代替的检查 |
| --- | --- | --- |
| 编译与类型检查 | 类型、签名、依赖和生成代码可以组合 | 业务结果与运行时装配 |
| 单元测试 | 隔离的业务规则、转换、编解码和失败结果 | Spring、数据库或外部设施的真实接入 |
| 装配测试 | Bean 选择、配置绑定、代理及启动条件 | 数据库约束和完整业务动作 |
| 集成测试 | Repository、事务、消息、缓存及模块协作的实际结果 | 页面布局和用户操作体验 |
| 构建 | 入口、依赖与资源能够生成目标产物 | 产物运行后的业务行为 |
| 页面检查 | 实际布局、焦点、交互和反馈 | 服务端权限与数据约束 |

涉及数据库专有语法、约束或锁的行为，需要在实际采用的数据库中验证。H2 或手写 mock 可以支持局部规则测试，不能证明 PostgreSQL 等数据库的专有行为。页面截图记录一个时刻的视觉结果，不能证明键盘操作、失败恢复或提交后的状态。

例如，单元测试验证「写入成功后调用消息发布者」，只能证明当前方法的调用顺序；它不能证明数据库事务回滚后消息是否仍会发出，也不能证明消息代理已经确认。后两项需要覆盖事务和消息接入的测试。

## 风险决定验证范围

局部规则变化通常由对应的公开行为测试验证；公开接口约定变化还涉及直接消费者；装配、迁移和构建入口变化需要相应的真实环境或产物检查。修改没有涉及的系统，不因为固定的测试组合而自动进入验证范围。

并发、重复投递、超时和节点退出影响结果时，单次成功路径不足以证明行为。状态命令需要核对不允许的当前状态，持久化写入需要核对零行、多行和竞争结果，外部操作需要核对失败后保留的数据及重试方式。

列表、树和批量任务的测试还应关注 SQL 与外部调用次数。只有少量测试数据时，执行时间短不能证明不存在 N+1；需要结合实际查询、批次上限和代表性数据量判断。

## 测试数据与结果

测试数据由当前场景创建，不依赖执行顺序、本机残留数据或其他测试的副作用。时间、随机数、ID 和外部返回影响预期结果时，使用可控输入。测试应观察最终数据与副作用，而不只验证内部方法被调用。

验证记录区分已经观察到的结果与尚未检查的行为。环境缺失、依赖未启动或工具不可用造成的失败，不表示代码已通过，也不自动表示实现有错；具体原因和剩余风险需要分别说明。
