# Vue、TypeScript 与交互规范

管理端日常实现遵守以下规则。页面状态、响应式、可访问性、设计令牌、真实 API 和浏览器验收的完整要求见[前端质量与交互设计完整规范](./frontend-quality-review)。

## 页面样式

界面优先清晰、可预测、及时反馈和可访问，不追求与业务无关的装饰。相同操作在不同页面使用一致组件、文案和反馈。

## 源码结构

`src/features/<domain>` 保存领域页面及其专属组件、组合式函数和测试。页面只负责数据加载、流程编排、路由协作和跨组件状态；独立表单、对话框、业务视图和可复用交互必须下沉到职责明确的组件。禁止把所有页面和组件平铺在 `src` 一级目录，也禁止把多个独立业务视图继续集中到一个页面组件。

跨领域组件按职责归入 `components/actions`、`components/avatar`、`components/data-display`、`components/data-entry`、`components/navigation` 和 `components/page`。只被单个领域使用的组件保留在该领域目录，不得为了“公共”名义提前上移。

路由按个人、平台、租户、系统和公共入口拆分定义，根路由文件只组合路由、守卫和工作区协作。Store 按稳定状态概念拆分；Session、Authentication、Workspace 等不得混入一个泛化 Store。语言根文件只组合公共与领域消息，规模较大的 `login`、`profile`、`accountSecurity` 等命名空间按领域和语言拆分。

## 页面状态

每个页面必须处理加载、空、成功、失败、无权限、资源失效和窄屏。列表、筛选、分页、主操作和风险操作形成完整信息结构。

## 及时反馈

提交后立即显示处理中，完成后显示明确成功或失败。长操作不得静默；后端可重试与否必须转成用户可理解动作。

## 高风险操作

删除、停用、发布、权限变化等使用二次确认，明确对象和后果，并与普通信息确认形成可见差异。409 冲突刷新最新数据并要求重新确认，禁止自动覆盖。

## 空状态与响应式

空状态说明为何为空和下一步。窄屏表格必须提供可读替代；不得仅依赖固定像素宽度或隐藏关键操作。

## 可访问性

使用语义控件、可见焦点、键盘路径、可访问名称和足够对比度。颜色不得作为唯一状态线索；错误消息与字段关联。

## 设计令牌

颜色、字号、间距、圆角和阴影使用统一 token。禁止在页面散落近似色值和重复 CSS 形成第二套设计系统。

## API Client

使用 `sca4d-admin/common` 和 OpenAPI 生成类型；ID 使用 string。页面不得创建独立 Axios、复制响应类型或直接猜后端错误结构。

## 页面验证

必须通过 lint、typecheck、单元测试和 build；关键流程执行 E2E 与真实浏览器验收，覆盖桌面、窄屏、失败、键盘和权限变化。
