# PostgreSQL 与数据库规范

## 表和字段

表和列必须对应需要长期保存的业务数据，不得照抄页面、临时流程或文档名词。通用主体引用使用 `principal_id`，领域角色通过类型和扩展表表达。

## 主键与引用

业务表使用集群 ID，ID 不编码租户、权限或业务状态。数据库不建立物理外键；Repository 在写入事务中校验引用目标及其有效状态，删除流程负责同步隔离和异步幂等清理。

## 状态与类型

有限值用明确字符串编码并由 Java 枚举统一转换。不得用展示中文、数组序号或不透明整数作为长期状态值。开放外部编码必须与有限枚举区分。

## 删除策略

仅在需要恢复、追溯或隔离唯一键复用时使用逻辑删除；查询与索引必须包含删除条件。只追加的记录禁止业务更新，临时关系可直接删除。

## 索引与完整性

数据库保留主键、唯一性、非空和查询索引，不使用 `CHECK` 表达有限类型或业务条件。索引以真实查询条件和排序为依据；逻辑删除唯一键使用合适的部分索引。有限类型由 Java 枚举转换，跨表引用和业务不变量由 Service、Repository、原子 SQL 与测试共同保证。

## Flyway

每次 schema 变化新增 `V<N>__<description>.sql`。已进入共享环境的迁移禁止修改。迁移应可在空 schema 连续执行，并从上一版本增量执行；构建门禁扫描全部迁移，禁止新增条件约束或物理引用关系。

## 数据修复

修复脚本明确目标集合、幂等性和失败行为。生产 Flyway 不依赖本机状态或手工先执行步骤。历史 checksum 冲突先辨别环境来源，不盲目 repair。
