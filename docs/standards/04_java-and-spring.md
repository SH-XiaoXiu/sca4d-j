# 04 Java 与 Spring 规范

用 Java 类型表达合法输入和状态，用构造器声明依赖，把事务放在负责完整业务动作的 Service。修改 Spring 代码时，重点检查调用是否经过代理、可选 Bean 怎样装配，以及失败后哪些数据和外部操作已经发生。

## Java 类型

系统定义且取值有限的状态、类型、模式和操作使用枚举或专用值类型。只有外部提供方、租户或协议可以增加新编码，且项目不能在编译时枚举时，才使用字符串。字段文档要说明编码来源和未知值的处理方式。

不使用 `Map<String, Object>`、反射或字符串约定绕过本来可以编译检查的契约。真正处理任意 JSON 的边界可以使用 Jackson 节点，但应尽快把已知字段转成命名清楚的类型。

项目不声明 Java `record`。需要值类型时使用普通类，在构造方法中表达输入条件，并根据真实行为实现相等性。

## 空值与 JetBrains 注解

引用类型的参数、返回值、字段和泛型元素根据真实情况使用 `@NotNull` 或 `@Nullable`。接口、实现、父类和覆盖方法的约定保持一致，不在实现中放宽输入或改变返回值的空值含义。

无副作用的方法可使用 `@Contract(pure = true)`；会修改当前对象或参数时准确声明 `mutates`。返回新对象、结果不应被忽略或集合不可修改时，根据实现使用 `@Contract`、`@CheckReturnValue` 和 `@Unmodifiable`。不为了注解数量添加与实现不一致的契约。

集合查询没有结果时返回空集合。「找不到」「无权限」「状态冲突」和「系统失败」使用不同结果或异常，不统一折叠为 `null`、`false` 或空集合。

## 类与接口

只在存在多个实现、跨模块调用方需要依赖长期契约，或具体应用必须提供扩展实现时，才增加 Java `interface`。同一模块中只有一个实现时，使用普通类通常更清楚。

接口说明调用方可以依赖的行为、数据变化和失败结果，不记录实现步骤。实现与接口完全一致时不复制文档注释；实现增加外部调用、特定锁或更严限制时，只补充该实现特有的部分。

## 依赖注入与自动配置

必需依赖使用构造器注入。可选扩展点使用 Spring 按类型提供的显式选择方式，并说明没有实现、同时存在多个实现和存在默认实现时的结果。业务代码不使用全局 Service Locator 或静态 Bean 访问器。

公共模块由自己的 AutoConfiguration 注册类型、扩展点和类型化配置。可选功能在依赖、配置或所需 Bean 不存在时明确不装配；不能要求所有 App 都声明某个具体业务 Bean。App 也不复制模块内部配置来替代公开装配入口。

## 类型化配置

模块配置使用 `@ConfigurationProperties`，前缀反映实际所有者：公共 Sca4d-J 模块使用 `sca4dj.*`，具体 App 可使用自己的前缀。配置类给出默认值、范围和失败结果，并由所属自动配置显式启用。

业务类不散落 `@Value` 字符串。同一默认值只在一个运行来源中定义，不在 Java、YAML、环境样例和常量中分别维护不同值。空值和错误值不能自动放宽认证、权限、Origin、密钥强度或外部访问限制。

## 事务与 Spring 代理

业务事务通常放在 Service 的公开方法上，使整个业务动作的数据库写入共同提交或回滚。Repository 可以为一个稳定的聚合存储操作声明独立事务，但不在 Repository 中加入业务权限、通知和外部调用。

只有跨 Spring Bean 调用才能依赖代理行为。不使用同一对象内部调用假设 `@Transactional`、`@Async`、缓存或自定义 AOP 会生效。调用顺序、锁范围和事务提交前后的副作用要能从主要流程直接看出。

## 序列化与协议转换

脚手架的持久化、Session 和内部消息使用 `@Sca4djJson Sca4djMapper`；该 Mapper 由脚手架定制，业务不依赖它。HTTP 与客户端协议使用各自配置的 `ObjectMapper`，普通业务代码通过注入复用对应 Mapper。Name、Code 与 Key 在内部保持类型，字符串转换只发生在配置、JSON、SQL 或协议边界；使用已有枚举 Codec、MyBatis TypeHandler 和 HTTP 响应转换，不通过反射或通用 Map 绕过类型。

协议输入在 Controller、消息适配或设备协议入口转成 Service 能够理解的类型。Service 不读取 ServletRequest、原始消息头、STOMP 帧或 MQTT 报文；需要保留的业务数据作为显式参数传入。

## 身份、Session 与 Token

业务代码依赖 Core 的 `AuthenticationAttempts`、`SessionLifecycle`、`Call` 和身份类型，不直接读取 Sa-Token Session 或自行解析 Token。Sa-Token 是 Auth 模块中的 Session 和 Token 实现细节；它不是其他模块建立平行身份模型的入口。

当前 Principal 只属于一次调用，由 Principal 选择和 `Call` 保存。不把当前 Principal、数据范围或请求局部状态写入长期 Token Session。

## 异常与失败

业务失败使用稳定错误码和能够区分条件的异常。内部依赖失败和外部系统失败保留操作对象、目标和是否可重试等必要上下文。Controller 不捕获所有异常后返回成功，底层异常文本、SQL、凭据和第三方完整响应不直接返回 HTTP 调用方。

异常不能被吞掉，也不能被伪装成空结果或成功。当前层将失败转为重试、降级或部分结果时，返回值、日志和文档都要说明当前影响与恢复方式。

## 完整评审

Java 文件还需按 [Java 工程评审](/standards/12_review)检查分层、公开 API、私有方法、框架生命周期、集群竞争、注释、日志和测试。编译通过只证明类型和签名成立，不代替这些检查。
