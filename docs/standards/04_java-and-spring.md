# 04 Java 与 Spring 规范

用 Java 类型表达合法输入和状态，用构造器声明依赖，把事务放在负责完整业务动作的 Service。修改 Spring 代码时，重点检查调用是否经过代理、可选 Bean 怎样装配，以及失败后哪些数据和外部操作已经发生。

## Java 类型

系统定义且取值有限的状态、类型、模式和操作使用枚举或专用值类型。只有外部提供方、租户或协议可以增加新编码，且项目不能在编译时枚举时，才使用字符串。字段文档要说明编码来源和未知值的处理方式。

不使用 `Map<String, Object>`、反射或字符串约定绕过本来可以编译检查的类型约定。接收任意 JSON 的协议入口可以使用 Jackson 节点；进入业务代码前，已知字段应转换成命名清楚的类型。

值类型的构造方式应表达输入条件；相等性只根据对象的真实取值实现。采用普通类或 Java `record` 时，均需确认序列化框架、空值约束和变更方式与该类型的用途一致。

## 空值与 JetBrains 注解

引用类型的参数、返回值、字段和泛型元素根据真实情况使用 `@NotNull` 或 `@Nullable`。接口、实现、父类和覆盖方法的约定保持一致，不在实现中放宽输入或改变返回值的空值含义。

无副作用的方法可使用 `@Contract(pure = true)`；会修改当前对象或参数时准确声明 `mutates`。返回新对象、结果不应被忽略或集合不可修改时，根据实现使用 `@Contract`、`@CheckReturnValue` 和 `@Unmodifiable`。不为了注解数量添加与实现不一致的注解约定。

集合查询没有结果时返回空集合。「找不到」「无权限」「状态冲突」和「系统失败」使用不同结果或异常，不统一折叠为 `null`、`false` 或空集合。

## 类与接口

Java `interface` 表达调用方需要依赖的稳定能力。存在多个实现、明确扩展点，或调用方不应依赖具体实现时，可以使用接口。同一模块中只有固定实现且调用方可直接依赖它时，普通类通常更清楚。

接口说明调用方可以依赖的行为、数据变化和失败结果，不记录实现步骤。实现与接口完全一致时不复制文档注释；实现增加外部调用、特定锁或更严限制时，只补充该实现特有的部分。

## 依赖注入与自动配置

必需依赖使用构造器注入。可选扩展点使用 Spring 按类型提供的显式选择方式，并说明没有实现、同时存在多个实现和存在默认实现时的结果。业务代码不使用全局 Service Locator 或静态 Bean 访问器。

例如，通知发送者可以是可选依赖，但「没有发送者」与「同时装配两个发送者」不能都悄悄选择第一个 Bean。前者可以按功能定义为不发送或启动失败；后者需要明确选择条件，否则运行结果取决于装配顺序。

公共模块由自己的 AutoConfiguration 注册类型、扩展点和类型化配置。可选功能在依赖、配置或所需 Bean 不存在时明确不装配；不能要求所有 App 都声明某个具体业务 Bean。App 也不复制模块内部配置来替代公开装配入口。

## 类型化配置

模块配置使用 `@ConfigurationProperties`，前缀反映实际所有者。配置类给出默认值、范围和失败结果，并由所属自动配置显式启用。具体前缀由项目配置参考规定。

业务类不散落 `@Value` 字符串。同一默认值只在一个运行来源中定义，不在 Java、YAML、环境样例和常量中分别维护不同值。空值和错误值不能自动放宽认证、权限、Origin、密钥强度或外部访问限制。

## 事务与 Spring 代理

业务事务通常放在 Service 的公开方法上，使整个业务动作的数据库写入共同提交或回滚。Repository 可以为一个稳定的聚合存储操作声明独立事务，但不在 Repository 中加入业务权限、通知和外部调用。

只有跨 Spring Bean 调用才能依赖代理行为。不使用同一对象内部调用假设 `@Transactional`、`@Async`、缓存或自定义 AOP 会生效。调用顺序、锁范围和事务提交前后的副作用要能从主要流程直接看出。

例如，`create()` 在同一个对象内调用带 `@Transactional` 的 `save()`，该内部调用不会经过 Spring 代理。若创建动作的全部写入必须共同回滚，事务应覆盖实际对外调用的业务方法，并由装配测试验证代理生效。

## 序列化与协议转换

持久化、Session、内部消息和 HTTP 可能采用不同的序列化配置。这些用途分别使用对应的 Mapper，并在进入业务代码前将已知字段转换为明确类型。名称、编码和键在内部保持类型，字符串转换发生在配置、JSON、SQL 或协议出入口；使用现有 Codec、TypeHandler 和响应转换，不通过反射或通用 Map 绕过类型。

需要持久化或跨实例恢复的结构应明确格式版本、当前写入版本和历史读取范围。JSON、消息、审计记录和设置数据分别使用自己的版本字段，不能混用。正常读取旧版本不自动迁移或写回；迁移任务负责事务、并发条件与保存结果，未知版本应明确失败。

敏感值加密还需区分密钥与算法、密文格式版本和业务用途。密文迁移的范围与写回时机由调用方显式指定，不在普通读取或启动时自动扫描全部数据。

协议输入在 Controller、消息适配或设备协议入口转成 Service 能够理解的类型。Service 不读取 ServletRequest、原始消息头、STOMP 帧或 MQTT 报文；需要保留的业务数据作为显式参数传入。

## 身份、Session 与 Token

业务代码依赖认证模块公开的身份、认证尝试和会话接口约定，不直接读取认证框架的内部 Session 或自行解析 Token。认证框架是实现细节，不是其他模块建立平行身份模型的入口。

当前身份及其访问范围只属于一次调用。需要跨调用保存的会话事实应单独定义；不把请求局部状态写入长期 Token Session。

## 异常与失败

异常类型、错误码、捕获位置和 HTTP 映射的完整规则见 [13 异常与失败](/standards/13_exceptions)。这里只保留 Java 层面的前提：异常不能被吞掉，也不能被伪装成空结果或成功；Controller 不捕获所有异常后返回成功。
