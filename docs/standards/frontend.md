# Vue、TypeScript 与交互规范

本页规定 `frontends/sca4d-admin` 中手写 TypeScript、Vue 页面、Store 和浏览器交互的写法。Sca4d Server Admin 的具体目录和运行方式见[管理端设计](/tutorials/admin-feature)，页面评审要求见[前端质量与交互评审](/standards/frontend)。

## 先使用 Vben 现有结构

Sca4d Server Admin 基于 Vue Vben Admin。布局、路由、菜单、权限、主题、表格、表单、弹窗、抽屉和通知优先使用 Vben 已有组件与接入方式。业务页面不复制一套布局，不用全局 CSS 改写 Vben，也不为已有组件再建立一层只转发参数的包装。

`internal/`、`packages/` 和构建脚本主要保存 Vben 通用代码。普通业务功能放在 `apps/sca4d-admin/`，只有确定属于整个前端工作区的通用修复才修改 Vben 公共部分。

## 目录职责

- `common/` 保存手写 HTTP 契约、`AdminApiClient`、错误类型、ETag 处理、业务 Controller 和与浏览器无关的 Port。它不能依赖 Vue、Pinia、Router 或 DOM。
- `apps/sca4d-admin/src/pages/` 保存路由直接加载的页面。页面组织查询、主要操作和页面级状态。
- `apps/sca4d-admin/src/features/` 保存由多个组件组成、可以独立命名的业务流程或视图。目前认证设置是这类内容；不为了缩短一个页面机械拆目录。
- `apps/sca4d-admin/src/store/` 保存 Session、认证和跨页面共享的业务状态。单个弹窗、筛选表单和临时选中项留在页面或组件中。
- `router/` 只声明路由、菜单元数据和守卫，不在路由文件中实现页面。
- `locales/` 保存界面文案。相同概念在菜单、标题、表单、提示和错误中使用同一名称。

新增文件前先找到仓库中职责相同的页面或 Controller，沿用它的目录、组件和错误处理方式。不要从 `examples/vue-vben-admin/` 复制演示数据、演示菜单或与 Sca4d Server 无关的页面。

## TypeScript 契约

`common/` 中的类型是手写契约，不由 OpenAPI 生成。后端请求、响应、状态编码或错误发生变化时，直接同步对应类型、Controller、测试和页面调用方。

- Java `long` 和 `Long` 使用 `Int64String`，不转换为 JavaScript `number`。
- 系统定义且取值有限的状态使用字符串联合类型，编码与后端一致。
- 可缺失值明确区分 `null` 和 `undefined`；不能用空字符串代替所有缺失情况。
- API 返回和 Controller 状态优先使用只读类型，避免页面无意修改共享数据。
- 不使用 `any`、宽泛字典或类型断言绕过未知响应。外部数据确实未知时先校验，再转换成项目类型。
- 导出的类型、函数、常量、Controller 操作和组合式函数按[注释与成品文档](/standards/comments-and-logging)编写中文 TSDoc。

## HTTP 与错误处理

页面和 Store 通过 `common/` 提供的 Controller 或 `AdminApiClient` 访问后端，不单独创建 Axios 实例，也不重复解析统一响应、Token、语言、ETag 和错误外壳。

`AdminError` 的种类用于决定界面行为：未认证清除失效 Session，权限不足保留页面上下文，资源不存在返回列表或关闭详情，版本冲突重新读取最新数据并要求用户确认。不能把所有失败都改写成同一条“请求失败”，也不能直接展示服务器异常或未知响应内容。

需要强 ETag 的修改先读取资源和 ETag，再使用 `If-Match` 提交。缺少 ETag 时停止修改并显示可恢复错误；412 或 428 不自动覆盖服务器数据。创建、更新和删除成功后，根据接口结果刷新当前列表、详情和相关共享状态。

## 页面与组件

路由页面负责当前页面的完整工作，但不应内联多个可以独立命名的复杂表单、确认流程或业务视图。拆分组件的依据是它是否有自己的输入、输出、状态和用户任务，不是代码行数。

跨页面复用的组件放入现有公共组件目录；只服务一个页面或一个 feature 的组件留在该位置。组件名称说明对象和用途，例如 `ActionVerificationDialog`，不用 `Content`、`Section1`、`CommonForm` 或 `Helper`。

Props、Emits 和双向绑定明确说明谁拥有状态。子组件不直接修改 Store 中与它无关的数据，也不通过事件总线或全局变量绕过页面协调。

## 异步状态

每个会发起请求的操作分别管理空闲、处理中、成功和失败状态。一个操作的 loading 不能误禁用另一个无关操作。例如 Passkey、Password、TOTP 和联邦登录各自保留自己的提交状态。

提交期间阻止相同意图的重复请求，但保留取消、关闭或其他安全操作。失败后保留用户已经填写且可以继续使用的内容；密码、验证码、Token 和 Client Secret 等秘密不保留在全局 Store、持久化存储或错误对象中。

列表和详情还要处理首次加载、重新加载、空结果、无权限、资源已经删除和局部操作失败。已有数据刷新失败时，除非数据已经不能安全使用，否则保留旧数据并明确显示刷新失败，不把页面清空伪装成空列表。

## 表单与高风险操作

字段校验靠近输入项，错误信息说明哪个值不符合什么条件。提交失败后焦点应能回到第一个需要修改的位置。按钮名称说明实际动作；“下一步”只能进入下一阶段，不能直接执行未说明的删除或提交。

删除、停用、覆盖、撤销凭据和结束 Session 等操作需要明确确认对象和影响。危险按钮只用于会造成数据、访问或凭据失效的动作。普通保存、验证和添加操作使用普通主按钮，不借用危险样式制造紧张感。

## 权限与路由

菜单、路由和按钮可以根据当前 Session 的权限隐藏或禁用，但后端仍执行最终权限检查。前端不根据角色名称、页面名称或本地推断扩大权限。

Session 或权限变化后，使用认证 Store 的统一刷新流程更新用户、权限、菜单、动态路由和页签。当前页面失去访问权限时跳转到仍允许访问的入口，不能只修改一个本地权限数组让其他状态继续使用旧值。

## 文案、时间与数字

界面文案使用用户能够理解的业务名称，不展示 Java 类名、内部状态名或单独错误码。中文和英文资源同步维护，不能让一种语言退化为消息键或机器翻译占位。

时间通过统一格式化入口显示，并明确采用浏览器时区还是固定业务时区。数量、金额和百分比使用适合语义的格式化；ID、版本号、验证码和电话号码不使用千分位。

## 验证

验证范围根据改动选择：

- 修改 `common/` 类型或 Controller 时，运行 `@sca4d/admin` 的类型检查和相关 Vitest；
- 修改 Vue 类型、Store 或页面逻辑时，运行管理端应用的类型检查和相关测试；
- 修改样式、布局或完整用户流程时，列出受影响页面、操作、状态和尺寸，由开发者人工验收；
- 修改 Vite、pnpm、路由入口或生产构建时，运行对应构建；
- 只修改文案或局部注释时，不固定运行全部前端任务。

实际命令以 `frontends/sca4d-admin/package.json` 为准。没有执行的检查在交付中说明原因，不能把类型检查、单元测试、构建和浏览器验收写成同一种证据。

## 前端质量与交互评审

本页用于评审修改过的页面、组件、Store、样式和交互。评审对象是本次改动可能影响的页面与用户流程，不要求每次前端修改都重新验收整个管理端。

### 评审页面整体

先完整阅读页面、相关组件、Store、`common/` Controller 和路由，再查看实际渲染结果。只读模板片段、CSS diff 或一张截图，无法判断页面在加载、失败和操作后是否正确。

页面首先应让用户看清当前对象、主要数据和可执行操作。管理后台保持安静、紧凑，便于反复查询和操作；不使用营销页式大标题、装饰性背景、卡片套卡片或与信息层级无关的阴影。

同类列表、筛选、详情、编辑和确认沿用 Vben 与现有业务页面的组件、位置和文案。新增设计只有在现有模式不能完成当前任务时才成立。

### 信息与操作

逐项检查：

- 页面标题、筛选条件、列表结果和主要操作之间的关系是否清楚；
- 同一页面是否只有一个明确的首要操作；
- 查询、重置、新增、保存、删除和启停是否与其他页面保持一致；
- 表格列是否只展示比较和操作所需的信息，详情字段是否放在详情或抽屉中；
- 操作菜单、图标按钮和批量操作是否容易发现，并有可访问名称；
- 空结果是否说明当前条件下没有什么，以及用户可以继续做什么；
- 页面是否泄露内部编码、HTTP 状态、Java 名称或无解释的错误码。

卡片只用于独立对象、统计项、模态内容或确实需要边框限定的工具。普通页面章节连续排列，不把每段文字放进悬浮卡片，也不在卡片内再嵌套相同样式的卡片。

### 请求状态与失败恢复

每个请求检查以下过程：

- 等待时间可被用户察觉时显示加载反馈；
- 提交期间阻止相同请求重复发送；
- 成功后更新当前列表、详情和必要的共享状态；
- 失败后保留仍可使用的输入和已加载数据；
- 校验错误能够定位到具体字段；
- 未认证、无权限、不存在、版本冲突和服务不可用给出不同的后续动作；
- 对话框关闭、路由离开或组件卸载后，不让过期响应覆盖新页面状态。

一个按钮或认证方式的 loading 只影响自身。不能因为 Passkey 请求正在处理，就禁用 Password、TOTP 或联邦登录；也不能用页面首次加载状态表示所有后续操作。

409、412 和 428 表示本地数据或前置条件已经不能直接使用。页面重新读取最新数据，让用户看到变化后再次决定，不能自动覆盖，也不能只显示成功提示。

### 表单和确认

表单标签、说明、单位、必填状态和错误信息应靠近对应字段。初始值来自当前资源时，要区分“尚未加载”“服务器返回空值”和“用户清空”。密码、验证码、Token 和 Secret 不回填、不写入日志，也不长期保存在 Store。

删除、停用、撤销凭据、结束 Session 和覆盖配置等高风险操作，需要显示具体对象及直接后果。确认按钮写明动作，例如“删除 Passkey”或“结束 Session”，不用含义模糊的“确定”。添加、验证和普通保存不使用危险按钮。

提交完成后，成功信息说明实际完成的动作。异步任务已经接收但尚未完成时，只提示“已提交”或对应状态，不提前提示最终成功。

### 响应式布局

根据改动影响检查桌面和移动布局；表格、抽屉、弹窗或复杂筛选变化时，再增加紧凑桌面和平板尺寸。各尺寸保留相同业务功能，布局可以变化，不能在移动端直接删除查询、详情或关键操作。

- 固定格式的表格、工具栏、分页、计数器和按钮保持稳定尺寸，加载状态不能推动相邻内容跳动；
- 长名称、邮箱、ID、错误信息和多语言文案可以换行或截断，并提供查看完整值的方式；
- 窄屏表格使用可横向滚动的清楚结构、信息列表或卡片替代，不能让关键列相互遮挡；
- 筛选较多时可以在窄屏进入抽屉，但已选条件和清除入口仍可看到；
- 移动端弹窗应为软键盘和底部提交按钮留出空间；
- 页面不能出现非预期横向滚动，固定导航和浮层不能遮住正文与操作。

### 可访问性

优先使用按钮、链接、输入框、表格和标题等语义元素。点击 `div` 需要补键盘行为和语义时，通常说明应改用现成控件。

- 所有操作可以使用键盘到达并执行；
- 焦点样式清楚，弹窗打开后进入弹窗，关闭后回到触发位置；
- 图标按钮有 `aria-label` 或可见 Tooltip；
- 表单 label 与输入项关联，错误信息能被辅助技术读取；
- 状态不只依赖颜色，还使用文字、图标或其他可辨认信息；
- 文本、控件和状态色在明暗主题下都保持足够对比；
- 动画尊重减少动态效果设置，不用动画阻碍操作。

### 样式与组件

颜色、字号、间距、圆角、边框和阴影使用 Vben 与项目已有 token。页面内不散落近似色值和只差少量尺寸的重复 CSS。确有独立业务含义的颜色或尺寸，应命名并集中定义。

紧凑面板、表格、抽屉和对话框使用与容器相称的字号，不把页面标题样式放进小卡片。圆角和阴影表达真实层级，不用来装饰每个区域。明暗主题都通过同一语义 token 表示主操作、成功、警告和错误。

按钮优先使用熟悉的图标表示撤销、刷新、下载、删除等操作，并为不熟悉的图标提供 Tooltip。明确命令可以使用图标与文字；不把每个选项都做成带文字的圆角按钮。

### 契约与权限

- 页面使用 `common/` 中的手写契约和 Controller，不复制响应类型或单独创建 HTTP 客户端；
- 64 位 ID 始终保持字符串；
- ETag、错误种类、状态编码和空值含义与后端一致；
- 页面不重新计算后端已经返回的权限、业务状态和计数；
- 菜单和按钮隐藏只改善体验，不能代替后端授权；
- 静态假数据、旧路由和仅在演示环境成立的分支不能进入正式业务页面。

### 选择验证方式

先说明改动可能破坏什么，再选择检查：

- 类型、Controller 或 Store 状态变化使用类型检查和相关 Vitest；
- 稳定的权限、状态转换和共享 Store 规则变化使用对应业务逻辑测试；
- 布局、主题、响应式或可访问性变化由开发者检查实际页面；
- AI 仅在任务明确要求时启动浏览器、Playwright 或 E2E，并限制在指定流程；
- 构建配置、入口、依赖或生产资源变化运行前端构建。

浏览器检查记录实际页面、尺寸、主题、数据状态和操作结果。截图可以证明当时的视觉结果，不能单独证明键盘、请求失败、权限变化和提交结果。

以下情况说明评审尚未完成：页面只验证成功状态；失败后无法继续操作；桌面和移动端功能不一致；关键内容溢出或遮挡；权限或 ETag 变化仍使用旧状态；检查失败没有说明原因；本次真正影响的页面或流程没有实际打开。
