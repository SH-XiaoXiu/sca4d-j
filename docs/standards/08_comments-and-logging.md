# 08 注释、文档注释与日志

文档注释告诉调用者怎样使用接口，逻辑注释解释必要条件与顺序，日志记录运行时实际发生的事件。写作时直接说明对象、动作、结果和失败影响；代码已经表达清楚的内容不再重复，秘密和完整请求不进入日志。

## 适用范围

本规范适用于项目中的 Java、Kotlin、TypeScript、JavaScript、Vue、SQL、XML、YAML、Properties、Shell、CSS 和 HTML 手写文件。

以下文件不手工修改：

- 根据 OpenAPI 或其他工具生成的文件；
- 第三方依赖、锁文件和二进制文件；
- `build`、`dist`、`node_modules`、运行数据等生成目录；
- 已经提交的 Flyway 版本迁移。修改迁移中的注释也会改变校验和，新迁移从创建时遵守本规范。

## 基本要求

注释只说明代码本身无法直接表达的事实，内容至少属于以下一种：

- 操作哪个业务对象或数据；
- 在什么条件下执行；
- 会修改什么状态；
- 失败后返回什么结果或保留什么数据；
- 为什么必须保持当前调用顺序；
- 调用方还需要执行什么操作。

能够通过准确名称表达的内容直接写进类名、方法名或字段名，不再增加一条重复注释。

所有手写注释使用中文。类名、方法名、字段名、数据库名、协议名、API 名称和错误码保留原文。

## 禁止表达

不要用抽象词代替具体行为，例如「赋能」「抓手」「收口」「承载」「治理」「闭环」「口径」「打通链路」「完成适配」或「提供能力」。代码标识符、正式协议名称和原始错误信息保留原文；其他表达应改写为实际方法、数据库表、状态变化、调用顺序、失败结果或用户可见结果。

禁止没有实际信息的注释：

```java
// 查询数据
Account account = repository.findAccount(accountId);

// 判断账号是否为空
if (account == null) {
    return;
}

// 返回结果
return account;
```

禁止在注释中保存下面的内容：

- 需求讨论和方案比较；
- 内部工作记录、审查过程和未完成指令；
- 已经删除的实现；
- 「以后优化」「暂时这样」「后续处理」等没有完成条件的计划；
- 对代码逐行进行中文翻译的说明。

## Java 文档注释

### 类型

需要供其他代码使用的具名类、接口、枚举和注解类型应有中文文档注释。注释说明该类型处理的对象、提供的操作及重要的数据变化。只服务局部实现且名称已经充分说明用途的类型，可以不重复写说明；匿名类不添加类型注释。

错误：

```java
/** Account 生命周期编排。 */
public class DefaultAccountService {
}
```

正确：

```java
/** 创建、更新、停用和删除 Account，并在认证材料变化后结束该 Account 的全部登录会话。 */
public class DefaultAccountService {
}
```

### 方法

以下方法应提供调用方需要的中文文档注释：

- 接口方法；
- 公开方法和受保护方法；
- 名称无法说明约束、顺序或失败结果的私有方法；
- 供框架反射调用但不能从普通调用关系看出的回调方法。

以下方法没有额外行为时不强制添加文档注释：

- 只把构造参数赋给同名字段的构造方法；
- 只读取或写入同名字段的 JavaBean getter/setter；
- 已经通过方法名或 `@DisplayName` 写清输入和预期结果的测试方法；
- 完全遵循父类或接口说明的 `@Override` 方法。

这些方法包含单位换算、空值转换、校验、缓存、状态修改或外部调用时，必须说明实际行为。

文档注释根据方法的真实行为说明：

- 调用前必须满足的条件；
- 参数代表的业务对象、单位、范围和特殊值；
- 返回值包含什么、不包含什么以及找不到数据时返回什么；
- 会修改的数据库记录、缓存、Session、文件或外部系统；
- 事务、锁、重复请求和调用顺序要求；
- 抛出每种异常的准确条件。

`@param`、`@return` 和 `@throws` 不重复 Java 类型和 JetBrains 注解已经表达的信息。

错误：

```java
/**
 * 获取 Account。
 *
 * @param id Account 主键，不能为空
 * @return Account
 */
```

正确：

```java
/**
 * 读取仍可登录的 Subject 默认资料。
 *
 * @param subjectId Subject 主键
 * @return 默认资料，不包含认证秘密和业务资料
 * @throws BizException Subject 不存在、已经删除或缺少 USER Principal 时抛出
 */
```

实现方法与接口行为完全一致时不复制接口注释。实现增加额外限制、外部调用或状态修改时，只补充该实现特有的说明。

私有方法用于隔离复杂条件、算法或协议数据转换时，说明调用处无法直接看出的约束。只为缩短方法而拆开的步骤应回到主要流程，不能用空泛注释解释其存在。

### 字段和枚举值

以下字段必须写中文文档注释：

- 公开常量；
- 配置字段；
- 枚举值；
- 名称无法说明单位、来源、范围或空值含义的数据字段。

注释写明数据来源、单位、范围、默认值、空值含义以及修改后的实际影响。依赖注入字段和名称已经完整表达含义的局部变量不添加注释。

## TypeScript 和 Vue 文档注释

以下内容必须提供中文 TSDoc 或相邻说明：

- 导出的类型、函数和常量；
- API 请求函数和返回数据转换；
- Store 中供页面调用的操作；
- 组合式函数；
- 组件 Props 和 Emits 中调用方无法从名称确定的限制；
- 异步组件对缓存、页面状态或其他组件产生的修改。

注释说明调用条件、请求参数、空值处理、失败结果和页面变化。名称已经清楚的局部状态、简单计算属性、直接转发的事件和模板标签不增加注释。

## 逻辑注释

逻辑注释放在相关代码块之前。注释说明原因和结果，不描述 Java、TypeScript 或模板语法。

以下逻辑必须根据实际情况写注释：

- 业务状态允许或禁止某项操作的原因；
- 权限检查使用的主体和资源；
- 事务失败后会一起回滚的修改；
- 乐观锁、分布式锁和重复请求的处理；
- 缓存删除或刷新时间；
- 消息、通知和页面刷新信号的发送时间；
- 异步请求的先后顺序和过期结果丢弃规则；
- 第三方协议要求保留当前写法的原因；
- 异常被转换、重试、忽略或继续抛出的条件。

示例：

```java
// 搜索词为空白时传入 null，Repository 收到 null 后不添加关键词查询条件。
String checked = StringUtils.hasText(search) ? search.trim() : null;
```

Vue 和 TypeScript 中同样说明实际结果：

```ts
// 新搜索开始后递增序号；较早请求即使更晚返回，也不能覆盖当前列表。
const requestId = ++latestRequestId
```

## 测试注释

测试方法优先通过方法名和 `@DisplayName` 写清输入、操作和预期结果，不再用文档注释重复一遍。

测试夹具、辅助类型和私有辅助方法遵守普通源码的文档注释要求。特殊准备顺序、模拟框架限制、时间推进和异常数据来源需要逻辑注释。

## 配置、SQL 和脚本注释

配置项说明写明用途、默认值、单位、可选值以及错误配置造成的结果。

SQL 注释说明不直观的数据修复条件、锁行为、数据库专用语法和失败后的处理。普通建表、增加字段和创建索引不逐句翻译。

脚本注释说明输入、输出、退出码、会修改的文件以及依赖的外部命令。显而易见的变量赋值和命令调用不添加注释。

## TODO

TODO 必须同时写明：

- 尚未完成的具体行为；
- 当前代码采用的处理方式及其影响；
- 开始修改所需的明确条件；
- 完成后应删除或替换的代码。

错误：

```java
// TODO 以后优化搜索
```

正确：

```java
// TODO 确认 Account 搜索字段和匹配方式后，替换当前四字段 ILIKE 查询并增加对应索引；完成后删除本注释。
```

## JetBrains 注解

接口和实现签名使用 `@NotNull`、`@Nullable` 等注解表达空值要求。接口、实现、参数和返回值保持一致。

已经由注解表达的「不能为空」不在文档注释中重复。`null` 表示使用默认值、清空字段或找不到记录等特殊行为时，文档必须说明实际含义。

## 日志

会执行实际处理过程的生产代码记录定位运行结果所需的日志。纯数据类型、常量、getter、setter、无副作用计算和没有独立运行意义的转发方法不为了数量打印日志。

消息使用 `中文事件描述 | key={} key={}` 格式，通过 SLF4J 参数占位符写入稳定字段。不记录完整对象、请求体、Credential、Token、密码、验证码和其他秘密。对象 ID、状态、数量、耗时和失败原因只在定位当前事件需要时记录。

- `TRACE` 记录执行器、拦截器、路由、协议、序列化和模块选择等框架内部过程。
- `DEBUG` 记录开发和诊断需要的条件、选择结果、命中数量和阶段。
- `INFO` 记录启动、关闭、模块启用、任务开始结束、重要状态变化和外部操作最终结果。
- `WARN` 记录仍可恢复、已降级或等待重试的结果，并写明当前影响和恢复方式。
- `ERROR` 记录当前流程无法恢复、重试耗尽、数据可能不一致或关键依赖不可用。

应用业务流程用 `DEBUG` 记录阶段和判断，用 `INFO` 记录值得默认观察的业务结果。普通查询不分别记录两条 `INFO`；循环内每条成功记录不使用 `INFO`。事务提交前只记录已发生的校验和写入，最终成功在能确认提交的位置记录。

例如，事务内写入 Outbox 时只成立「消息已登记」；代理确认后才成立「消息已发布」。等待重试属于可恢复结果，适合记录当前影响与下次处理条件；重试耗尽后再记录最终失败。日志措辞随着实际状态变化，不用同一条「发送成功」覆盖这些阶段。

同一个异常只在最终处理它的位置记录一次。继续向上抛出的底层代码不重复打印堆栈，也不把失败伪装成空结果或成功。

### 来源和字段

使用当前类的 logger，不用自定义 topic 隐藏来源，也不在每条消息中重复手写模块名。日志来源的格式由应用配置负责；业务代码不扫描调用栈推断实际类名。

字段名称使用 camelCase，同一对象在不同类中使用相同名称。顺序为对象或任务标识、状态和版本、数量及耗时、技术目标，异常对象放最后。启动横幅可以独立排版，运行事件仍使用单行格式。

```java
log.error(
        "Quartz 计划同步失败，保留数据库记录等待下次同步 | scheduleId={} schedulerName={}",
        scheduleId,
        schedulerName,
        exception);
```

DEBUG 参数需要昂贵序列化或遍历时，先检查 `log.isDebugEnabled()`。TRACE 同样只记录类型、长度、结果和必要标识，不输出完整协议帧、请求或响应。

### 业务阶段和异步结果

后台批次、调度任务、消息消费和跨系统同步应能从日志判断开始、关键决策、状态变化、外部操作及最终结果。普通同步查询只记录有诊断价值的条件和结果，不机械增加开始、完成两条日志。

```java
log.info("Subject 关系清理批次开始 | claimedCount={} batchSize={}", claimedCount, batchSize);
log.debug("Subject 清理任务跳过，已由其他节点处理 | taskId={} version={}", taskId, version);
log.info("Subject 关系清理批次完成 | successCount={} retryCount={} durationMs={}", successCount, retryCount, durationMs);
```

批量任务分别记录成功、跳过、重试和失败数量，为失败项保留可关联标识。异步提交区分已受理、开始执行、完成、重试中和失败；事务内写入 Outbox 只能记录已登记，收到代理确认后才能记录发布完成。

当前层吞掉异常并转换成重试、降级或部分结果时，由当前层记录影响和恢复方式。正常的校验失败、未找到和无权限不在多个层重复打印 WARN。

### 事务提交后动作与日志

提交后动作应使用项目统一的事务回调入口，并明确调用时是否要求已有事务。事务尚未提交时，不能把可能回滚的写入记录成最终成功；没有事务时，回调入口应按其公开约定执行或失败。

提交后回调在进程退出时可能丢失，不提供持久化重试。必须可靠完成的事件和跨系统操作使用 Outbox 或持久任务；回调不应假设原事务仍可继续写入数据库。回调失败是否传播，以及多个回调如何执行，由所选入口的约定说明。

只有重要数据库结果必须等提交后才成立，且值得默认观察时，才在提交后记录 `INFO`。普通写入可用 `DEBUG` 描述「已写入事务」。提交后日志不作为审计记录、可靠事件、恢复依据或消息投递证明；日志消息不能把尚未完成的外部副作用写成成功。提交后动作只携带已经冻结的 ID、状态、版本、数量或短文本，不携带可变对象、完整 Payload 或秘密。

使用专门的提交后日志机制时，按所用机制的参数、Marker 和事务要求登记。允许丢失的缓存刷新或通知应由负责该动作的代码记录失败及恢复方式；调用方不能把已提交的事务表述为回滚。

### 请求与后台任务

请求日志复用现有 MDC 中的 `callId`、`subjectId`、`accountId` 和 `principalId`，不在每条消息中重复拼接。后台任务使用真实的 scheduleId、executionId、taskId、messageId、batchId 或节点标识，不伪造 HTTP 请求关系；异步线程不隐式继承可能已经失效的请求 MDC。

HTTP 访问日志记录路径、状态和耗时，操作审计记录执行者、目标和动作。业务阶段日志仍需说明状态变化、投递结果与外部依赖错误。

### 敏感数据和验收

禁止记录 Authorization、Cookie、私钥、签名密钥、完整签名 URL、数据库凭据、完整请求响应、消息或审计 Payload，以及无排障必要的手机号、邮箱、证件号和文件内容。需要识别外部值时，使用内部 ID、长度、类型、摘要或经过确认的脱敏值。

ERROR 保留原始异常及 cause、堆栈；在产生异常的入口避免把秘密和完整第三方响应写进异常消息。HTTP 只返回安全错误码与文案。开发 SQL 日志仅用于本地开发数据，不在包含生产秘密或个人数据的环境开启参数、结果输出。日志级别和文件位置由目标项目的运行配置规定；临时调整 logger 后恢复默认级别。

新增或修改业务流程时同时检查整个流程的日志。缺少阶段与结果、INFO 被高频明细淹没、重复异常、事务提交前报告成功、泄露敏感内容，或新增只转发 SLF4J 的包装层，均不满足提交条件。
